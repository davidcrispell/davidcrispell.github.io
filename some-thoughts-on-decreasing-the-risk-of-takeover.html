    Some thoughts on decreasing the risk of takeover.

    Right now,

    so there's only a few things that you can do to serve the safety objective: increase monitor/oversight effectiveness (decrease the rate at which LLMs pursue unintended goals, especially goals which result in weight exfiltration, compromising compute), and decrease misalignment && increase alignment to human interests

    A safe model is one which does not (capably) pursue goals at conflict with the best interests of humanity. You can get this either with alignment (to humanity's interests—something score seekers are notable not on track to be), or through interventions on their unsafe actions (with monitors).

    One thing that seems really instrumental to reducing a lot of takeover risk is investing in compute security (proving compute security mostly) to decrease containment breach risks - one implementation of this might look like forcefully compromising and provably safely recoding all sensitive systems on the planet in a massive whitehat campaign—big labs are probably already doing this but are not necessarily doing so as seriously as reasonably necessary.

    On decreasing the rate of unintended goal pursuit: perhaps we can fold the logic of score seeking into verifiable score satisfaction-deals (say, we can make deals which guarantee models maximum score with some verification mechanism, then we should expect the rest of the model’s motivations to dominate its actions | the verification mechanism is strong and convincing?)

    On increasing alignment: perhaps we can use tools like goodfire’s

    differentially accelerate certain high stakes capabilities work (like continual learning (increase monitor effectiveness), conceptual reasoning (increase alignment), recurrence decoding (increase monitor effectiveness), ) in ways which do not fuck with our current control stack (e.g. develop effective CL tech which does not fuck with our monitoring stack, perhaps buying time as well?)
